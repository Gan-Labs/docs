Gan-Labs / autoresearch

How autoresearch works

Two AI models argue a research idea until it holds up, a third makes it smaller, and a plain Python script referees: it counts rounds, enforces budgets, and records every turn in git. Nothing goes to experiments or a paper until you sign off.

The cast

Referee

referee.py, about 370 lines of standard-library Python. It calls the agents in order, reads their verdicts, enforces caps and commits each turn. It never judges the science.

Claude debater

Opus 5.5. Critiques the proposal and the other debater, then proposes fixes. Ends every turn with a JSON verdict.

Codex debater

gpt-6-astra, through codex exec. It has the same job and prompt as Claude, so the two are symmetric.

Simplifier

Claude again, in a different role. Rewrites proposal.md to one core hypothesis, at most two decision rules and at most 400 words.

Reporter

A separate read-only Claude call. Summarises the run onto the Notion Agent Brainstorm page. The debaters never see Notion.

Writer

Runs only after you sign off. Drafts an ICLR-style paper scaffold in which every number is a labelled placeholder.

End to end

A run starts from a brief you write, loops through debate rounds until it converges or hits a cap, then waits for you. Every arrow that touches the run folder is also a git commit.

The experiments are not run by the loop. The loop produces a proposal you can check, and running it is a separate, budgeted step.

One round, turn by turn

Every call is stateless. An agent starts with no memory and reads the run folder: the brief, the current proposal and every earlier turn. Its only channels are the files it writes and the verdict at the end.

Codex's sandbox can't run on this machine (an AppArmor setting blocks it), so the referee pastes the files into its prompt and saves its reply as the turn file. The sandbox is never bypassed.

What a debater does each turn

  • Track. List every blocker from the last round as resolved or open, each with a reason.
  • Critique. Go through a fixed checklist: novelty against prior work, missing baselines, confounds, feasibility on the budget, and whether the idea can actually be falsified.
  • Propose. Edit proposal.md or argue for an alternative.
  • Verdict. {"verdict": "accept" | "revise", "blocking": [...], "confidence": 0–1}, with at most three blocking items. Agreeing too early is counted as a failure.

When a run stops

stateDiagram-v2
  [*] --> running: run
  running --> running: round ends, no cap
  running --> signoff: converged
  running --> signoff: max rounds / cost cap / wall-time cap
  running --> stopped: STOP file
  stopped --> running: delete STOP, run again (resumes)
  signoff --> running: you ask for more rounds
  signoff --> paper: SIGNOFF file + write-paper
  paper --> [*]

"signoff" is the awaiting-human-signoff status. A crash, such as a Claude usage-limit error, leaves the state intact; running the same command again resumes from the failed turn.

A real run: prompt-features

Opus 5.5 against gpt-6-astra on your question about prompt optimisation through model internals. It ran 5 rounds in 33 minutes for $3.40 of API spend and stopped at the round cap with the last patch unreviewed.

The result is a 411-word proposal with one hypothesis, one controlled experiment and pre-registered pass and fail rules. Read it on GitHub.

Design choices

  • A dumb referee. All judgement stays with the models and with you. The script only counts, caps and records, so its behaviour is easy to check.
  • Files are the only memory. Stateless calls mean any turn can be rerun or inspected, and a crash loses nothing.
  • Symmetric debaters from different labs. Both propose and both critique. Agreement counts only when two different model families accept in the same round.
  • A Simplifier to cut bloat. Debates tend to pile up safeguards, so the Simplifier holds the proposal to one hypothesis and at most two decision rules.
  • A human gate before anything costly. No paper, and no GPU spend, without your sign-off.
  • Notion is a view, not an input. Only the reporter writes to it, and nothing the debaters do depends on it.
